# 任务ID获取机制（核心规则）

## ⚠️ 执行原则

**本文件按任务ID存储多个任务详情，不决定执行哪个任务。AI必须按以下步骤执行**：

### 第一步：从上下文提取任务ID（强制执行）

**检查方式**：
| 检查项 | 说明 |
| --- | --- |
| 上一轮 AI 输出 | 检查上一轮输出首行是否包含 `任务ID: task_xxxxxxxx` |
| IDE 会话上下文 | IDE 自动携带上一轮输出的任务ID |
| 用户输入引用 | 用户是否引用了包含任务ID的历史输出 |

### 第二步：根据提取结果处理

| 提取结果 | 处理方式 |
| --- | --- |
| **无任务ID**（新会话、或上下文无任务ID） | → **创建新任务** |
| 有任务ID → 本文件存在对应任务详情块 | → **继续已有任务** |
| 有任务ID → 本文件不存在对应任务详情块 | → **创建新任务** |

### 第三步：执行

**创建新任务**：
1. 生成新任务ID `task_{新随机ID}`
2. 在本文件追加新任务详情块：`<!-- TASK_{新ID}_START --> ... <!-- TASK_{新ID}_END -->`
3. 从 Stage 0 开始执行
4. **首行输出必须携带任务ID**：`[阶段名称] 任务ID: task_xxx`

**继续已有任务**：
1. 查找对应的任务详情块 `<!-- TASK_{任务ID大写}_START -->`
2. 读取执行状态和阶段进度
3. 根据阶段继续执行
4. **首行输出必须携带任务ID**：`[阶段名称] 任务ID: task_xxx`

## ⚠️ 禁止行为

- **禁止**：读取本文件后直接使用某个任务（必须先从上下文提取任务ID）
- **禁止**：假设用户想继续某个任务（必须先检查上下文任务ID）
- **禁止**：输出时不携带任务ID（每条输出首行必须有任务ID）

# 状态更新指南

## 新增任务时更新

在本文件追加新任务详情块：复制模板，替换任务ID为新ID

## 阶段进入时更新

找到对应任务的详情块（`<!-- TASK_{任务ID大写}_START -->`），更新：
- `**正在执行**: {阶段名称}`
- `**当前阶段**: stage{N}`
- `**阶段状态**: in_progress`
- `**下一步计划**: {下一步动作}`
- 阶段进度：将当前阶段移到"进行中"

## 阶段完成后更新

- `**阶段状态**: completed`（或 `waiting_user`）
- 阶段进度：将当前阶段移到"已完成"，下一阶段移到"进行中"

## 回退时更新

- `**当前阶段**: stage{目标阶段}`
- `**阶段状态**: in_progress`
- `**重置阶段**: [stageX, stageY, ...] → 待重新执行`
- 阶段进度：将后续阶段移到"待重新执行"

## 任务完成时更新

将任务详情块移至"已完成任务"区域，添加完成时间
