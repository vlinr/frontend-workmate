# 状态更新指南

## 阶段进入时更新

找到对应任务的状态块（`<!-- TASK_{任务ID}_START -->`），更新：
- `**正在执行**: {阶段名称}`
- `**阶段**: stage{N}`
- `**状态**: in_progress`
- `**下一步**: {下一步动作}`
- 阶段进度：将当前阶段移到"进行中"

## 阶段完成后更新

- `**状态**: completed`（或 `waiting_user`）
- 阶段进度：将当前阶段移到"已完成"，下一阶段移到"进行中"

## 回退时更新

- `**阶段**: stage{目标阶段}`
- `**状态**: in_progress`
- `**重置阶段**: [stageX, stageY, ...] → 待重新执行`
- 阶段进度：将后续阶段移到"待重新执行"

## 任务查找规则

更新状态时：
1. 从上下文获取 `current_task_id`
2. 查找 `<!-- TASK_{任务ID大写}_START -->`
3. 若找到 → 更新该状态块
4. 若未找到 → 新增任务状态块

## 新会话任务关联规则

**新会话启动 → 首先检查状态文件是否有活跃任务**

### 从用户输入提取任务ID

| 用户输入模式 | 动作 |
| --- | --- |
| 包含 `任务ID: task_xxxxxxxx` | 继续该任务 |
| 引用包含任务ID的 AI 输出 | 从引用内容中提取任务ID，继续该任务 |
| 无任务ID引用 | **创建新任务**（默认行为） |

### 示例场景

**场景 1：继续已有任务**
```
用户："继续刚才的任务"（引用了先前 AI 输出："任务ID: task_abc123"）
AI：提取 task_abc123 → 读取状态文件 → 查找 TASK_ABC123 块 → 从记录的阶段继续
```

**场景 2：新任务**
```
用户："添加用户管理模块"（无任务ID引用）
AI：未提取到任务ID → 生成新任务ID → 新增任务块 → 从 Stage 0 开始
```

**场景 3：显式任务ID**
```
用户："继续 任务ID: task_def456 的任务"
AI：提取 task_def456 → 读取状态文件 → 查找 TASK_DEF456 块 → 从记录的阶段继续
```

### 为什么这样设计有效

- **每条 AI 输出携带任务ID**：即使上下文超限，任务上下文也不会丢失
- **用户可引用任务ID**：显式引用或通过引用 AI 输出
- **默认：新任务**：避免将无关的新请求强制关联到现有活跃任务
- **状态文件只追踪，不强制**：状态文件 `alwaysApply: true` 提供规则，但实际任务关联由用户输入上下文决定
