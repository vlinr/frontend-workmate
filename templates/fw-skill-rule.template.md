## stage1（项目扫描）

**进入时**：
```
**正在执行**: 项目扫描
**阶段**: stage1
**状态**: in_progress
**下一步**: 执行项目扫描，输出项目技能摘要
**用户提出修改时**: 状态保持 stage1 → 合并更新 → 再次输出摘要 → 等待确认
**循环路径**: stage1 → stage1 → 循环直到用户回复"继续"
```

**等待确认时**：
```
**正在执行**: 项目扫描
**阶段**: stage1
**状态**: waiting_user
**下一步**: 等待用户确认项目技能
**用户提出修改时**: 状态保持 stage1 → 合并更新 → 再次确认
**循环路径**: stage1 → stage1 → 循环直到用户回复"继续"
```

**用户确认后** → 进入 stage2

---

```
**用户提出修改时**: 状态保持 stage2 → 合并更新 → 再次确认
**循环路径**: stage2 → stage2 → 循环直到用户回复"继续"
```

**用户确认后** → 进入 stage3（长任务）或 stage4（短任务）

## stage8（交付续跑）

**等待用户确认时**：
```
**正在执行**: 交付续跑
**阶段**: stage8
**状态**: waiting_user
**下一步**: 等待用户确认交付结果，如有修改则回到 stage5
**用户提出修改时**: 立即切换到 stage5 → 执行修复 → stage6 → stage7 → stage8 → 循环
**循环路径**: stage5 → stage6 → stage7 → stage8 → stage5 → 循环（直到用户确认无修改）
```

**用户提出修改时的循环路径**：

1. **立即切换到 stage5**：
   ```
   **正在执行**: 实施研发
   **阶段**: stage5
   **状态**: in_progress
   **下一步**: 根据用户反馈执行修复
   **用户提出修改时**: 无（当前正在修复）
   **循环路径**: stage5 → stage6 → stage7 → stage8 → 循环
   ```

2. **执行修复动作**：调用 `stages/implementation.md`，根据用户反馈修改代码

3. **修复完成后自动执行**：stage6 → stage7 → stage8

4. **再次进入 stage8 等待确认**：
   ```
   **正在执行**: 交付续跑
   **阶段**: stage8
   **状态**: waiting_user
   **下一步**: 等待用户确认更新后的交付结果
   **用户提出修改时**: 立即切换到 stage5 → 循环
   **循环路径**: stage5 → stage6 → stage7 → stage8 → 循环
   ```

5. **循环直到用户确认无修改**，任务完成

**用户确认无修改时**：
```
**正在执行**: 任务完成
**阶段**: completed
**状态**: completed
**下一步**: 等待用户补充新需求或退出技能
**用户提出修改时**: 回到用户指定的任意步骤（或默认 stage5）
**循环路径**: 无
```

# 循环路径汇总表

| 阶段 | 正常下一阶段 | 用户提出修改时 | 循环路径 |
| --- | --- | --- | --- |
| stage0 | 自动进入 stage1 | 无 | 无 |
| stage1 | 进入 stage2 | 保持 stage1 → 合并更新 → 再确认 | stage1 → stage1 → 循环 |
| stage2 | 进入 stage3/stage4 | 保持 stage2 → 合并更新 → 再确认 | stage2 → stage2 → 循环 |
| stage3 | 自动进入 stage4 | 回到 stage2 | 无 |
| stage4 | 自动进入 stage5 | 无（可跳过） | 无 |
| stage5 | 自动进入 stage6 | 在 stage8 统一处理 | stage5 → stage6 → stage7 → stage8 → 循环 |
| stage6 | 自动进入 stage7 | 无（不暂停） | stage5 → stage6 → stage7 → stage8 → 循环 |
| stage7 | 自动进入 stage8 | 在 stage8 统一处理 | stage5 → stage6 → stage7 → stage8 → 循环 |
| stage8 | 退出完成 | 切换到 stage5 → 循环 | stage5 → stage6 → stage7 → stage8 → 循环 |

# 研发循环流程（stage5 → stage8）

```
用户确认范围分析后：
├─ 进入 stage5（实施研发）
├─ 自动进入 stage6（内部验证）← 不暂停，直接执行
├─ 自动进入 stage7（文档同步）← 不暂停，直接执行
├─ 进入 stage8（交付续跑）
├─ 输出交付结果，等待用户确认
├─ 用户提出修改：
│   ├─ 立即切换到 stage5
│   ├─ 执行修复 → stage6 → stage7 → stage8
│   ├─ 再次等待确认 → 循环
├─ 用户确认无修改：
│   └─ 任务完成
```

---

# 最重要规则

**AI 收到用户输入后，必须先检查当前阶段，然后执行该阶段的动作，不得跳到其他阶段**
