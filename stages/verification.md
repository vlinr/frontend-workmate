# Stage 6：内部验证

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含验证内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "文档更新计划" | 禁止输出文档阶段的内容 |
| "用户确认后会xxx" | 禁止幻想用户反馈 |

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出：`[内部验证] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID

### 3. 完成后自动进入下一阶段

**验证完成后**：
- 不输出确认提示语
- 不等待用户确认
- 自动进入 stage7（文档同步）

---

## 目标

- 在交付前验证修改真实有效
- **完成后自动进入 stage7，不暂停等待用户确认**

---

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：更新状态文件

**首先更新状态文件**：

根据当前任务ID找到对应的状态块：
- 查找 `<!-- TASK_{任务ID大写}_START -->` 到 `<!-- TASK_{任务ID大写}_END -->` 之间的内容
- 使用 edit 工具替换该状态块内容为：

```
**任务ID**: {当前任务ID}
**正在执行**: 内部验证
**阶段**: stage6
**状态**: in_progress
**下一步**: 执行功能验证、lint/type/build/test
```

---

### 步骤 2：加载相关技能

**⚠️ 重要：验证开始前，需要加载项目技能获取验证约束**

执行以下动作：

1. 加载技能 `fw-project-develop` 了解项目构建规则和验证约束
2. 从技能中获取项目构建规则和验证约束
3. 了解项目的 lint/type/build 配置

---

### 步骤 3：执行验证动作

**⚠️ 重要：以下验证需按顺序执行，特殊验证涉及技能调用**

---

#### 3.1 埂础校验

执行以下动作：

1. lint 校验
2. type 校验
3. build 校验

---

#### 3.2 功能验证

执行以下动作：

1. 功能正确性验证
2. 关键交互验证
3. 回归路径验证

---

#### 3.3 特殊验证 ⚠️ 技能加载节点

**⚠️ 重要：根据改动类型，必须判断是否需要加载验证技能**

**判断改动类型**：

| 改动类型 | 具体判断条件 |
| --- | --- |
| **页面/组件改动** | 涉及用户界面渲染；涉及视觉元素；涉及用户交互组件；涉及页面结构 |
| **样式/UI 改动** | 涉及样式定义；涉及布局调整；涉及视觉设计；涉及主题/配色/字体配置 |

**⚠️ 注意**：
- 以上判断条件适用于所有前端技术栈（React/Vue/Angular/Svelte 等）
- 具体文件格式不限（可以是 .tsx/.vue/.jsx/.svelte 等）
- 具体样式格式不限（可以是 .css/.less/.scss/.stylus 等）

**根据判断结果执行技能调用**：

| 改动类型 | 需加载的技能 | 加载动作 |
| --- | --- | --- |
| 页面/组件改动 | `fw-accessibility` | 加载技能 `fw-accessibility` 检查 WCAG 无障碍访问性 |
| 样式/UI 改动 | `fw-web-design-guidelines` | 加载技能 `fw-web-design-guidelines` 审计 UI 设计规范 |

**执行动作**：

1. 根据上述表格判断当前改动类型

2. 若涉及**页面/组件改动**：
   - 加载技能 `fw-accessibility` 检查 WCAG 无障碍访问性
   - 根据技能指导验证改动是否符合无障碍标准

3. 若涉及**样式/UI 改动**：
   - 加载技能 `fw-web-design-guidelines` 审计 UI 设计规范
   - 根据技能指导验证改动是否符合 UI 设计规范

4. 若无特殊验证需求：
   - 跳过技能加载，继续输出验证结果

**⚠️ 禁止事项**：
- ❌ 禁止跳过技能加载直接输出验证结果
- ❌ 禁止不判断改动类型就加载技能

---

### 步骤 4：处理验证结果

**根据验证结果，决定下一步**：

| 验证结果 | 下一步动作 |
| --- | --- |
| 全部通过 | 输出验证结果 → 自动进入下一阶段（stage7） |
| 代码问题失败 | 回到 stage5 修复 → 重新执行验证流程 |
| 环境问题失败 | 输出环境修复建议 → 停留在 stage6 等待修复 |

---

### 步骤 5：输出验证结果并自动进入下一阶段

**验证通过后，输出结果并自动进入 stage7**：

```
[内部验证] 任务ID: {当前任务ID}
验证完成。

验证结果：
- lint: 通过
- type: 通过
- build: 通过
- 功能验证: 通过

接下来进入下一阶段：[文档同步]。
```

---

### 步骤 6：更新状态文件为下一阶段

**进入 stage7 前更新状态文件**：

```
**任务ID**: {当前任务ID}
**正在执行**: 文档同步
**阶段**: stage7
**状态**: in_progress
**下一步**: 判断是否更新项目技能 + 生成目录说明文档
```

---

## 禁止事项

- 禁止在 stage6 暂停等待用户确认
- 禁止输出"请确认验证结果"

---

## 回退条件

- 若任一关键验证失败，返回 Stage 5，修复后自动执行 Stage 6 → Stage 7 → Stage 8
- 若失败原因属于环境阻塞，输出环境修复建议，停留在 Stage 6 等待修复
