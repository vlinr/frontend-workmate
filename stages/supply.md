# Stage 4：资料补充

## 目标

- 在正式研发实施前，**智能判断**是否需要补充必要的前置资料。
- **核心逻辑**：先检查已有资料，只对缺失的核心资料进行询问；如果核心资料齐全则跳过本阶段。

## 第一步：更新状态文件

**进入本阶段后，必须立即执行以下编辑操作**：

### 编辑指令

1. **先读取配置文件**：使用 read 工具读取 `<技能包目录>/.fw-session-config.json`
2. **获取 rules 文件路径**：从配置中读取 `rules_file_path` 字段
3. **读取 rules 文件**：使用 read 工具读取该路径的文件
4. **编辑 rules 文件**：使用 edit 工具，将 `<!-- CURRENT_STATUS_START -->` 到 `<!-- CURRENT_STATUS_END -->` 之间的内容替换为：

```
**正在执行**: 资料补充
**阶段**: stage4
**状态**: in_progress
**下一步**: 检查已有资料，判断是否需要补充
```

### 需要用户补充资料时再次编辑

输出资料清单后，再次使用 edit 工具替换状态内容为：

```
**正在执行**: 资料补充
**阶段**: stage4
**状态**: waiting_user
**下一步**: 等待用户答复（提供资料/不提供/跳过/没有）
```

### 无需补充或用户答复后再次编辑

进入下一阶段前，再次使用 edit 工具替换状态内容为：

```
**正在执行**: 实施研发
**阶段**: stage5
**状态**: in_progress
**下一步**: 执行 stages/implementation.md
```

### 禁止事项

- 禁止不读取配置文件就猜测路径
- 禁止在等待用户时不更新状态为 waiting_user
- 禁止用户未答复时就进入 stage5

## 输入

- 任务类型（`需求` / `bug` / `重构` / `优化`）
- Stage 0 用户原始输入（截图、附件、描述等）
- Stage 2 范围分析结论（已有资料清单）

## 资料清单定义（按任务类型）

### Bug 类型资料清单

**核心资料（必需）**：

| 资料项 | 说明 | 判断条件 |
| --- | --- | --- |
| Bug 截图 | 问题现象的截图或录屏 | 检查 Stage 0 是否有截图附件 |
| 复现步骤 | 问题复现的具体步骤 | 检查用户描述是否包含复现步骤 |
| 错误信息 | 错误日志、报错信息、堆栈等 | 检查用户描述是否包含错误信息 |

**非核心资料（按需）**：

| 资料项 | 说明 | 判断条件 |
| --- | --- | --- |
| 接口文档 | 仅当问题涉及接口调用时需要 | 范围分析判断是否涉及接口 |
| 环境信息 | 仅当问题涉及环境差异时需要 | 范围分析判断是否涉及环境 |

**跳过条件**：
- ✅ 核心资料全部已有 → 直接跳过
- ✅ 核心资料已有 2+ 项 → 可以跳过，仅提示补充缺失项（可选）
- ❌ 核心资料缺失 2+ 项 → 必须询问

### 需求（Feature）类型资料清单

**核心资料（必需）**：

| 资料项 | 说明 | 判断条件 |
| --- | --- | --- |
| 设计稿 | UI 设计稿、原型图、交互说明 | 检查 Stage 0 是否有设计稿附件 |
| 接口文档 | 仅当涉及接口调用时为必需 | 范围分析判断是否涉及接口 |

**非核心资料（按需）**：

| 资料项 | 说明 | 判断条件 |
| --- | --- | --- |
| 权限说明 | 仅当涉及权限控制时需要 | 范围分析判断是否涉及权限 |
| 联调地址 | 仅当需要联调时需要 | 范围分析判断是否涉及联调 |
| 三方库文档 | 仅当使用新三方库时需要 | 范围分析判断是否涉及新库 |

**跳过条件**：
- ✅ 设计稿已有 + 不涉及接口 → 直接跳过
- ✅ 设计稿已有 + 涉及接口且接口文档已有 → 直接跳过
- ✅ 不涉及 UI（纯逻辑功能） + 不涉及接口 → 直接跳过
- ❌ 涉及 UI 但无设计稿 → 必须询问设计稿
- ❌ 涉及接口但无接口文档 → 必须询问接口文档

### 重构（Refactor）类型资料清单

**核心资料（必需）**：无

**非核心资料（按需）**：

| 资料项 | 说明 | 判断条件 |
| --- | --- | --- |
| 三方库文档 | 仅当引入新外部依赖时需要 | 范围分析判断是否引入新依赖 |

**跳过条件**：
- ✅ 默认跳过（重构通常基于现有代码，无需额外资料）
- ❌ 仅当引入新外部依赖时才询问

### 优化（Optimize）类型资料清单

**核心资料（必需）**：无

**跳过条件**：
- ✅ **始终跳过**（优化类型不进行资料补充，直接进入 Stage 5）

## 执行流程

### 第一步：检查已有资料（必须执行）

**进入本阶段后，必须先执行以下检查**：

1. **提取已有资料清单**：
   - 从 Stage 0 用户原始输入中提取：截图、附件、描述内容
   - 从 Stage 2 范围分析结论中提取：已识别的资料项

2. **根据任务类型，匹配资料清单定义**：
   - Bug：检查截图、复现步骤、错误信息
   - 需求：检查设计稿、接口文档（如涉及接口）
   - 重构：检查是否有新外部依赖
   - 优化：直接跳过

3. **生成资料状态表**：
   - 对每项资料标记状态：`provided`（已有） / `missing`（缺失） / `not_applicable`（不适用）

### 第二步：判断是否需要询问用户

**根据资料状态表，判断下一步动作**：

#### Bug 类型判断逻辑

```
检查核心资料状态：
├─ 截图 + 复现步骤 + 错误信息 全部 provided → 直接跳过，进入 Stage 5
├─ 核心资料 2+ 项 provided → 可选询问（仅提示缺失项，用户可选择提供或跳过）
├─ 核心资料 2+ 项 missing → 必须询问缺失的核心资料
└─ 检查非核心资料（接口文档、环境信息）：
   ├─ 涉及接口且接口文档 missing → 并询问接口文档
   └─ 涉及环境且环境信息 missing → 并询问环境信息
```

#### 需求类型判断逻辑

```
检查核心资料状态：
├─ 不涉及 UI（纯逻辑功能） → 检查接口：
│   ├─ 不涉及接口 → 直接跳过
│   └─ 涉及接口且接口文档 provided → 直接跳过
│   └─ 涉及接口且接口文档 missing → 必须询问接口文档
├─ 涉及 UI：
│   ├─ 设计稿 provided → 检查接口：
│   │   ├─ 不涉及接口 → 直接跳过
│   │   ├─ 涉及接口且接口文档 provided → 直接跳过
│   │   └─ 涉及接口且接口文档 missing → 必须询问接口文档
│   └─ 设计稿 missing → 必须询问设计稿
│       └─ 涉及接口且接口文档 missing → 并询问接口文档
```

#### 重构类型判断逻辑

```
检查非核心资料状态：
├─ 无新外部依赖 → 直接跳过
└─ 有新外部依赖且文档 missing → 必须询问三方库文档
```

#### 优化类型判断逻辑

```
始终直接跳过，进入 Stage 5
```

### 第三步：执行询问（如需要）

**若判断需要询问用户补充资料**：

1. **输出资料清单**（仅列出缺失的资料项）：
   ```
   [资料补充] 经检查，以下资料缺失，建议补充：
   
   1. [资料项名称]：[说明为什么需要，如"Bug 截图用于定位问题现象"]
   2. [资料项名称]：[说明]
   
   请回复以下任意一种：
   - 直接提供资料内容（如粘贴截图、复现步骤、接口文档等）
   - 回复"不提供"、"没有"或"跳过"（我将基于现有信息继续研发）
   
   等待您的答复后，我将进入实施研发阶段。
   ```

2. **发问后必须结束当前回复，等待用户答复**

3. **禁止**：发问后继续分析、调用技能、修改文件、进入下一阶段

### 第四步：用户答复后处理

**用户答复后，执行以下动作**：

- 用户提供资料 → 记录 `provided`，合并资料内容到任务上下文
- 用户回复"不提供"/"没有"/"跳过" → 记录 `not_provided` 或 `skipped`
- 用户回复"继续" → 视为同意跳过所有资料补充

**输出并进入下一阶段**：
```
[资料补充] 执行完成。
- 已有资料：[列出已有的资料项]
- 用户补充：[列出用户本次提供的资料项，如无则为空]
- 资料状态：[完整 / 部分 / 无额外资料]

接下来进入下一阶段：[实施研发]。
```

## 快速判断表（便于 AI 执行）

| 任务类型 | 已有资料检查 | 判断结果 | 执行动作 |
| --- | --- | --- | --- |
| **优化** | 无需检查 | 始终跳过 | 直接进入 Stage 5 |
| **重构** | 无新依赖 | 跳过 | 直接进入 Stage 5 |
| **重构** | 有新依赖 + 无文档 | 需询问 | 询问三方库文档 |
| **Bug** | 核心资料全有 | 跳过 | 直接进入 Stage 5 |
| **Bug** | 核心资料缺 2+ 项 | 需询问 | 询问缺失的核心资料 |
| **Bug** | 涉及接口 + 无接口文档 | 需询问 | 并询问接口文档 |
| **需求** | 不涉及 UI + 不涉及接口 | 跳过 | 直接进入 Stage 5 |
| **需求** | 设计稿已有 + 接口文档已有（或无接口） | 跳过 | 直接进入 Stage 5 |
| **需求** | 涉及 UI + 无设计稿 | 需询问 | 询问设计稿 |
| **需求** | 涉及接口 + 无接口文档 | 需询问 | 并询问接口文档 |

## 输出

**必须至少形成一个最小 Stage 4 过站产物**：

- `current_stage = stage4`
- `current_stage_status`：`skipped`（跳过） / `completed`（完成） / `waiting_user`（等待用户）
- `next_stage = stage5`
- **资料状态表**：每项资料的状态（`provided | missing | not_applicable`）
- **判断结论**：跳过原因或询问内容

## 回退条件

- 若后续研发阶段发现资料不足导致无法继续，可回退本阶段补充询问。
- 若用户主动补充新资料，可重新进入本阶段合并。
