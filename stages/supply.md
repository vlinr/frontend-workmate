# Stage 4：资料补充

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含资料补充内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "实现方案" | 禁止输出实现阶段的内容 |

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出：`[资料补充] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID

### 3. 根据资料状态决定是否等待用户答复 ⚠️ 强制规则

**⚠️ 重要：若核心资料缺失，必须等待用户答复**

两种执行路径：

| 资料状态 | 执行路径 |
| --- | --- |
| 核心资料齐全 | 自动跳过，进入 stage5 |
| 核心资料缺失 | **必须等待用户答复** |

**禁止事项**：
- ❌ 禁止在核心资料缺失时跳过用户询问
- ❌ 禁止不输出提示语就继续执行

---

## 目标

- 在正式研发实施前，**智能判断**是否需要补充必要的前置资料
- **核心逻辑**：先检查已有资料，只对缺失的核心资料输出提示语提示用户

---

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：更新状态文件

**首先更新状态文件**：

根据当前任务ID找到对应的状态块：
- 查找 `<!-- TASK_{任务ID大写}_START -->` 到 `<!-- TASK_{任务ID大写}_END -->` 之间的内容
- 使用 edit 工具替换该状态块内容为：

```
**任务ID**: {当前任务ID}
**正在执行**: 资料补充
**阶段**: stage4
**状态**: in_progress
**下一步**: 检查已有资料，判断是否需要补充
```

---

### 步骤 2：检查已有资料

**根据任务类型，检查资料清单**：

#### 2.1 Bug 类型资料清单

| 资料项 | 判断条件 |
| --- | --- |
| Bug 截图 | 检查 Stage 0 是否有截图附件 |
| 复现步骤 | 检查用户描述是否包含复现步骤 |
| 错误信息 | 检查用户描述是否包含错误信息 |

#### 2.2 Feature 类型资料清单

| 资料项 | 判断条件 |
| --- | --- |
| 设计稿 | 检查 Stage 0 是否有设计稿附件 |
| 接口文档 | **输出提示语提示用户是否涉及接口，不能自行推断** |

#### 2.3 Refactor 类型资料清单

| 资料项 | 判断条件 |
| --- | --- |
| 三方库文档 | 仅当引入新外部依赖时需要 |

#### 2.4 Optimize 类型资料清单

**始终跳过**（优化类型不进行资料补充）

---

### 步骤 3：判断是否需要提示用户补充资料

**根据任务类型和资料状态，判断下一步动作**：

#### 3.1 Bug 类型判断逻辑

| 核心资料状态 | 下一步动作 |
| --- | --- |
| 截图 + 复现步骤 + 错误信息 全部 provided | 直接跳过 → 输出衔接提示语进入下一阶段 |
| 核心资料 2+ 项 provided | 可选提示（仅提示缺失项） |
| 核心资料 2+ 项 missing | 输出提示语提示缺失的核心资料 |

**非核心资料判断**：

| 非核心资料 | 判断条件 | 处理方式 |
| --- | --- | --- |
| 接口文档 | 用户未明确是否涉及接口 | 输出提示语："此 Bug 是否涉及接口调用？" |
| 接口文档 | 用户明确确认"涉及接口" + 接口文档 missing | 输出提示语提示接口文档 |
| 环境信息 | 用户明确确认"涉及环境问题" + 环境信息 missing | 输出提示语提示环境信息 |

#### 3.2 Feature 类型判断逻辑

| 资料状态 | 下一步动作 |
| --- | --- |
| 不涉及 UI（纯逻辑功能） + 用户确认不涉及接口 | 直接跳过 → 输出衔接提示语进入下一阶段 |
| 设计稿已有 + 用户确认不涉及接口 | 直接跳过 → 输出衔接提示语进入下一阶段 |
| 设计稿已有 + 用户确认涉及接口 + 接口文档已有 | 直接跳过 → 输出衔接提示语进入下一阶段 |
| 涉及 UI + 无设计稿 | 输出提示语提示设计稿 |
| 设计稿已有 + 用户未确认是否涉及接口 | 输出提示语提示是否涉及接口 |
| 用户确认涉及接口 + 接口文档 missing | 输出提示语提示接口文档 |

**⚠️ 前端界面开发的提示规则**：
- 前端界面（页面、组件）开发通常涉及数据交互
- 不能自行判定"不涉及接口"
- 输出提示语："此页面是否涉及接口调用（数据获取、表单提交等）？"

#### 3.3 Refactor 类型判断逻辑

| 资料状态 | 下一步动作 |
| --- | --- |
| 无新外部依赖 | 直接跳过 → 输出衔接提示语进入下一阶段 |
| 有新依赖 + 无文档 | 输出提示语提示三方库文档 |

#### 3.4 Optimize 类型判断逻辑

**始终跳过**（直接输出衔接提示语进入下一阶段）

---

### 步骤 4：输出提示语（如需要） ⚠️ 若输出提示语则必须等待用户答复

**⚠️ 重要：若判断需要提示用户补充资料，必须先输出提示语，然后等待用户答复**

若判断需要提示用户补充资料，执行以下动作：

#### 4.1 输出资料清单

```
[资料补充] 经检查，以下资料缺失，建议补充：

1. [资料项名称]：[说明为什么需要]
2. [资料项名称]：[说明]

请回复以下任意一种：
- 直接提供资料内容
- 回复"不提供"、"没有"或"跳过"
```

**输出提示语后结束当前回复，等待用户答复**

**⚠️ 禁止事项**：
- ❌ 禁止输出提示语后继续执行其他操作
- ❌ 禁止跳过用户询问环节

#### 4.2 前端界面开发的提示模板

**若涉及前端界面开发，输出以下提示语**：

```
[资料补充] 已检测到设计稿。
请确认以下问题：
1. 此页面是否涉及接口调用？（如：数据获取、表单提交、状态查询等）
   - 回复"涉及接口" → 我将提示接口文档
   - 回复"不涉及接口" → 直接进入研发阶段
2. 此页面是否涉及权限控制？
   - 回复"涉及权限" → 我将提示权限说明
   - 回复"不涉及权限" → 跳过此项
```

---

### 步骤 5：用户答复后处理

**用户答复后，执行以下动作**：

| 用户回复 | 处理方式 |
| --- | --- |
| 提供资料 | 记录 `provided`，合并资料内容到任务上下文 |
| "不提供"/"没有"/"跳过" | 记录 `not_provided` 或 `skipped` |
| "继续" | 视为同意跳过所有资料补充 |

---

### 步骤 6：输出衔接提示语并自动进入下一阶段

**资料补充完成后（或跳过），输出衔接提示语**：

```
[资料补充] 任务ID: {当前任务ID}
资料补充完成。

资料状态：
- 已有资料：[列出已有的资料项]
- 用户补充：[列出用户本次提供的资料项]
- 资料状态：[完整 / 部分 / 无额外资料]

接下来进入下一阶段：[实施研发]。
```

---

### 步骤 7：更新状态文件为下一阶段

**输出衔接提示语后，更新状态文件**：

```
**任务ID**: {当前任务ID}
**正在执行**: 实施研发
**阶段**: stage5
**状态**: in_progress
**下一步**: 执行 implementation.md
```

---

### 步骤 5-等待：需要等待用户答复时 ⚠️ 必须等待用户答复

**⚠️ 重要：若需要等待用户答复，必须先输出提示语，然后结束当前回复**

若需要等待用户答复，执行以下动作：

1. 输出资料缺失提示语（已在步骤 4.1 输出）
2. 更新状态文件为 waiting_user：
   ```
   **正在执行**: 资料补充
   **阶段**: stage4
   **状态**: waiting_user
   **下一步**: 等待用户答复
   ```
3. **结束当前回复，等待用户答复**

**⚠️ 禁止事项**：
- ❌ 禁止输出提示语后继续执行其他操作
- ❌ 禁止跳过用户询问环节

---

## 回退条件

- 若后续研发阶段发现资料不足导致无法继续，可回退本阶段输出提示语补充资料
