# Stage 1：扫描仓库与项目

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含项目扫描内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "页面实现计划" | 禁止输出实现阶段的内容 |
| "接下来要开发xxx" | 禁止输出未来阶段的计划 |
| 任务分解列表 | 禁止自创任务列表 |
| "验证和优化" | 禁止输出验证阶段的内容 |

**正确输出**：
```
[项目扫描] 任务ID: task_xxxxxxxx
正在扫描项目...
[项目扫描] 已生成项目技能 fw-project-develop。
请确认是否可以继续进入下一阶段：[范围分析]。
```

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出必须包含任务ID：`[项目扫描] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID
- 禁止脱离任务上下文执行操作

### 3. 必须等待用户确认 ⚠️ 强制规则

**⚠️ 重要：项目技能生成后，必须等待用户确认才能进入下一阶段**

项目技能生成后：
- 输出项目技能摘要
- 输出确认提示语
- **结束当前回复**
- **等待用户回复"继续"或提出修改**

**禁止事项**：
- ❌ 禁止输出摘要后直接进入下一阶段
- ❌ 禁止跳过用户确认环节

---

## 目标

- 以当前项目的固定项目技能名 `fw-project-develop` 作为本阶段主产物
- **项目技能存放位置**：存放于【技能目录】
- 若已有项目 skills，则先检查是否仍可复用、是否需要刷新
- 若尚无项目 skills，则扫描项目并生成首版 `fw-project-develop`

---

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：更新状态文件

**首先更新状态文件**：

根据当前任务ID找到对应的状态块：
- 查找 `<!-- TASK_{任务ID大写}_START -->` 到 `<!-- TASK_{任务ID大写}_END -->` 之间的内容
- 使用 edit 工具替换该状态块内容为：

```
**任务ID**: {当前任务ID}
**正在执行**: 项目扫描
**阶段**: stage1
**状态**: in_progress
**下一步**: 检查项目技能是否存在
```

---

### 步骤 2：检查项目技能是否存在

**先执行以下检查，再决定后续分支**：

1. **检查【技能目录】是否已存在固定项目技能名** `fw-project-develop`
2. **检查【技能目录】是否已有历史项目技能候选**

---

### 步骤 3：项目技能已存在时的处理流程

**当项目技能已存在时，执行以下流程**：

#### 2.1 验证技能是否过期

- 检查【工作目录】下的前端项目根目录是否存在（与技能记录一致）
- 检查核心入口文件是否存在（如 `package.json`、`src/main.*`、`src/index.*`）
- 检查技术栈标识是否变化（读取 `package.json` 的 dependencies/devDependencies 关键字段）

**判断结果**：
- 若以上锚点均无变化 → 技能可复用 → 输出摘要 → 输出衔接提示语进入下一阶段
- 若任一锚点变化 → 技能需要刷新 → 执行增量扫描 → 刷新技能 → 输出衔接提示语进入下一阶段

---

### 步骤 3：项目技能不存在时的处理流程

**⚠️ 重要：当项目技能不存在时，必须执行以下流程，不能跳过任何判断**

---

#### 3.1 扫描并识别前端项目数量

**执行以下动作**：

1. 扫描【工作目录】下的前端项目（检测 `package.json`、`src/`、构建配置等）
2. **记录识别到的前端项目数量和路径**
3. **⚠️ 扫描完成后必须立即进入判断分支，不能继续执行其他操作**

---

#### 3.2 根据识别结果进入对应分支 ⚠️ 判断分支点

**⚠️ 重要：扫描完成后，根据识别到的项目数量，必须进入以下其中一个分支**

| 识别结果 | 进入分支 | 关键动作 |
| --- | --- | --- |
| 识别到 1 个前端项目 | → **分支A（下方）** | 锁定项目 → 输出提示语 → **等待用户答复** |
| 未识别到前端项目 | → **分支B（下方）** | 输出提示语 → **等待用户答复** |
| 识别到多个前端项目 | → **分支C（下方）** | 列出项目 → 输出提示语 → **等待用户答复** |

**⚠️ 禁止事项**：
- ❌ 禁止扫描后直接读取项目文件
- ❌ 禁止扫描后直接生成项目技能
- ❌ 禁止跳过判断分支直接执行后续步骤

---

##### 分支A：识别到唯一前端项目时 ⚠️ 必须等待用户答复

**⚠️ 重要：此分支必须先询问用户，不能直接扫描项目内容**

当识别到唯一前端项目时，执行以下动作：

1. 锁定该项目路径
2. **立即输出以下提示语**：
   ```
   已锁定前端项目：[项目路径]。

   你可以直接回复提供项目 skills、项目文档或其他项目约束，我将优先采用您的资料生成项目技能。
   如果你不提供，我将基于【工作目录】内容分析并生成。
   ```
3. **结束当前回复，等待用户答复**

**⚠️ 禁止事项**：
- ❌ 禁止输出提示语后继续分析项目结构
- ❌ 禁止输出提示语后直接扫描项目
- ❌ 禁止输出提示语后生成项目技能
- ❌ 禁止跳过用户询问环节

---

###### 用户答复后执行项目扫描（仅在用户答复后执行）

**⚠️ 此步骤仅在用户答复后才执行，不是步骤3的后续**

用户答复后，按以下方式处理：

| 用户回复 | 执行动作 |
| --- | --- |
| 提供项目 skills/文档/约束 | 优先读取用户资料 → 生成 `fw-project-develop` |
| 明确"不提供"/"跳过"/"没有" | 执行项目扫描流程 → 生成 `fw-project-develop` |
| 空回复或"继续" | 视为"不提供"，执行项目扫描流程 |

**项目扫描流程**（用户答复后才执行）：

**⚠️ 重要：以下每个步骤需要按顺序执行，不能跳过**

1. **读取项目核心文件**
   - 读取 package.json 获取依赖和脚本
   - 读取入口文件（src/main.tsx、src/index.tsx、src/App.tsx 等）

2. **分析项目结构和技术栈**
   - 加载技能 `fw-code-analysis-doc` 分析目录结构并获取指导
   - 根据技能指导分析项目目录结构
   - 提取技术栈信息（框架、语言、UI库等）
   - 分析模块关系和依赖关系

3. **生成 fw-project-develop 技能文件**
   - 将分析结果写入 fw-project-develop/SKILL.md
   - 记录项目结构、技术栈、入口文件等关键信息

**执行完成后进入步骤4**

---

##### 分支B：未识别到前端项目时 ⚠️ 必须等待用户答复

**⚠️ 重要：此分支必须先询问用户意图**

当未识别到前端项目时，执行以下动作：

1. **立即输出以下提示语**：
   ```
   [项目扫描] 未在【工作目录】下识别到前端项目。

   请回复您的意图：

   1. 若要创建新项目，请提供技术栈：
      - 框架：React / Vue / Angular / Svelte
      - 语言：TypeScript / JavaScript
      - UI库：Ant Design / Element Plus / Tailwind CSS 等
      
      示例："创建项目：React + TypeScript + Ant Design"

   2. 若不想创建项目，回复"不创建"或"跳过"

   3. 若有现有项目，请提供路径："路径是：xxx"
   ```
2. **结束当前回复，等待用户答复**

**⚠️ 禁止事项**：
- ❌ 禁止输出提示语后继续执行其他操作
- ❌ 禁止跳过用户询问环节

---

###### 用户答复后提取内容（仅在用户答复后执行）

**⚠️ 此步骤仅在用户答复后才执行**

**从用户回复中提取两类信息**：

| 信息类型 | 提取规则 | 处理方式 |
| --- | --- | --- |
| **初始化信息** | 技术栈、框架、语言、UI库等 | 当前阶段（stage1）立即处理 |
| **研发需求信息** | 功能需求、页面描述等 | 记录到任务上下文，等 stage2 处理 |

**根据用户意图执行**：

| 用户回复 | 执行动作 |
| --- | --- |
| 提取到技术栈 | 执行项目初始化 → 执行项目扫描 → 生成项目技能 → 输出衔接提示语进入下一阶段 |
| 回复"退出"或"结束" | 终止流程 |
| 回复"跳过"或空回复 | 采用默认方案（React + TypeScript + Ant Design）→ 执行初始化 |
| 提供现有项目路径 | 切换路径重新扫描 |
| 仅研发需求，无技术栈 | 输出提示语补充技术栈 |

---

##### 分支C：识别到多个前端项目时 ⚠️ 必须等待用户选择

**⚠️ 重要：此分支必须先询问用户选择项目，不能自动选择**

当识别到多个前端项目时，执行以下动作：

1. 列出所有识别到的前端项目路径
2. **立即输出以下提示语**：
   ```
   已识别到多个前端项目：
   1. [项目路径1]
   2. [项目路径2]
   ...

   请回复本次基于哪个项目继续（回复项目路径或序号）。
   ```
3. **结束当前回复，等待用户答复**

**⚠️ 禁止事项**：
- ❌ 禁止输出提示语后自动选择项目
- ❌ 禁止跳过用户询问环节

**用户答复后**：锁定用户选择的项目 → 进入分支A的处理流程（输出提示语询问用户是否提供资料）

---

### 步骤 4：输出项目技能摘要并等待用户确认 ⚠️ 必须等待用户确认

**⚠️ 重要：生成项目技能后，必须等待用户确认才能进入下一阶段**

**⚠️ 此步骤仅在项目技能生成后才执行，不是步骤3的后续**

生成项目技能后，执行以下动作：

#### 4.1 更新状态文件为等待用户

```
**任务ID**: {当前任务ID}
**正在执行**: 项目扫描
**阶段**: stage1
**状态**: waiting_user

#### 4.2 输出摘要并附加确认提示语

```
以上是本阶段的结论：已生成项目技能 fw-project-develop。

请确认是否可以继续进入下一阶段：[范围分析]。
- 如有偏差或补充，请直接告诉我。
- 如无其他修改，回复"继续"即可。
```

**输出提示语后结束当前回复，等待用户确认**

**⚠️ 禁止事项**：
- ❌ 禁止输出摘要后直接进入下一阶段
- ❌ 禁止跳过用户确认环节

**输出提示语后结束当前回复，等待用户确认**

---

### 步骤 5：用户确认循环机制

**用户答复后，按以下方式处理**：

| 用户回复 | 处理动作 |
| --- | --- |
| 回复"继续" | 输出衔接提示语进入下一阶段 |
| 提出修改或问题 | 合并用户反馈 → 更新 fw-project-develop → 再次输出摘要 |

#### 5.1 用户提出修改时的处理流程

1. 更新状态为 in_progress
2. 执行合并更新：读取用户反馈 → 合并到 `fw-project-develop`
3. 再次输出摘要
4. 再次进入等待状态
5. 循环直到用户回复"继续"

---

**用户回复"继续"后**：

#### 6.1 更新状态文件

**任务ID**: {当前任务ID}
**正在执行**: 范围分析
**阶段**: stage2
**状态**: in_progress
**下一步**: 执行 ./scope-analysis.md
```

#### 6.2 输出衔接提示语

```
[项目扫描] 执行完成。接下来进入下一阶段：[范围分析]。
```

## 通用扫描规则（所有分支遵循）

**在执行项目扫描时，遵循以下规则**：

1. **优先读取目录说明文档**：
   - 在扫描任何目录前，先检查该目录下是否存在说明文档（如 `README.md`、`AGENTS.md`）
   - 若存在说明文档 → 优先读取说明文档获取目录信息

2. **调用代码分析技能**：
   - 当需要分析目录结构、提取技术栈、理解模块关系时，调用技能 `fw-code-analysis-doc` 分析目录并生成说明文档
   - 调用目的：提升分析准确度，减少遗漏

## 项目技能失效判定

以下情况表明项目技能需要刷新：

- 【工作目录】下的前端项目根目录、核心目录结构或入口文件已明显变化
- 技术栈、构建方式、路由方案、权限模型、状态管理方案发生变化
- UI 框架类型、框架版本、组件主入口或自研框架目录发生变化
- 现有项目技能缺少本次任务必需的关键目录路由或研发约束
- 用户提供了新的项目 skills、项目文档、UI 框架文档或 UI 框架 skills
- 用户明确指出项目技能内容不准确或已过期

---

## 通用规则（所有分支）

1. 本阶段只允许把"稳定项目知识"写入 `fw-project-develop`，不得写入当前任务的临时改法或实现偏好

2. Stage 1 完成条件是：`fw-project-develop` 已确认存在、可复用、已刷新或新生成，并已交用户确认

3. 若尚未生成/刷新技能或未等待用户确认，不得进入 Stage 2

4. 若识别到 UI 库或自研组件体系，判断是通用库还是自研框架：
   - 通用库：记录名称与版本
   - 自研框架：判断是否需要输出提示语提示用户文档/skills

5. 若用户尚未回答 UI 框架资料问题（`pending`），停留本阶段

6. 若用户纠正项目理解或发现技能过期，重新执行本阶段并刷新技能

7. 使用以下模板作为分析脚手架：
   - `../templates/project/project-skill-template.md`
   - `../templates/project/project-ui-skill-template.md`

## 回退条件

- 若实现阶段发现项目技能与真实结构不一致，回退本阶段重扫并刷新项目技能
- 若后续发现初始化选型、项目技能来源或 UI 框架结论失真，回退本阶段重扫并刷新对应技能
- 若本阶段依赖的用户输入缺失、变更或被撤回，回到本阶段重新输出提示语
