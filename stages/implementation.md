# Stage 5：实施研发

## 目标

- 根据任务类型与项目规则执行实际代码修改。

## 技能强制调用规则（不得跳过）

**本阶段必须根据实际条件调用以下技能，不得跳过**：

| 触发条件 | 必须调用的技能 | 说明 |
| --- | --- | --- |
| 项目技能存在 | `fw-project-develop` | **必须先调用**，获取项目结构、技术栈、路由、权限、构建规则等约束 |
| 任务类型为 `bug` | `systematic-debugging` | bug 任务必须先调用系统化调试技能，找到根因后再修复 |
| 技术栈为 React（项目技能中标记） | `react-best-practices` | **仅适用于 React 技术栈**，React 项目实现必须遵循 React 最佳实践 |
| 技术栈为 React 且涉及组件开发或修改 | `react-components` | **仅适用于 React 技术栈**，创建或修改组件时必须遵循组件规范 |
| 涉及复杂类型约束或类型问题 | `typescript-advanced-types` | 类型推导、泛型、条件类型等复杂场景必须调用 |
| 缺少关键技能 | `find-skills` | 发现缺失技能时必须输出安装建议 |

**项目技能说明**：
- `fw-project-develop` 是项目技能，包含项目结构、技术栈、路由、权限、状态管理、构建规则等关键信息
- **必须调用**：本阶段开始时必须先调用项目技能，理解项目约束后再开始实现
- 调用目的：让 AI 理解项目约束，避免违背项目已有规则

**技术栈说明**：
- `react-best-practices`、`react-components` **仅适用于 React 技术栈**（项目技能中标记）
- 其他技术栈（Vue、Angular、Svelte 等）目前暂无对应技能
- 技术栈判断依据：调用 `fw-project-develop` 后获取的技术栈字段

**禁止事项**：
- 禁止因为"Stage 2 没有指定"就跳过技能调用
- 禁止以"时间紧迫"为由跳过技能调用
- 禁止在不满足触发条件时强行调用（避免过度调用）
- 禁止在非 React 技术栈下调用 React 技能

## 分流规则

- `bug`
  - **必须**先调用 `systematic-debugging` 找到根因
  - 若涉及复杂类型问题，**必须**辅以 `typescript-advanced-types`
- `feature`
  - 参考 `rules/frontend-implementation.md` 执行实现流程
  - 若技术栈为 React（项目技能中标记），**必须**调用 `react-best-practices`（仅适用于 React）
  - 若技术栈为 React 且涉及组件开发，**必须**调用 `react-components`（仅适用于 React）
- `refactor`
  - 参考 `rules/frontend-implementation.md` 执行实现流程
  - 默认先保持行为不变
  - 先拆影响范围，再分批实施
  - 若技术栈为 React，同样遵循 React 技能调用规则

## 通用动作

1. **开始正式实现前，必须先调用项目技能 `fw-project-develop`**：
   - 项目技能包含项目结构、技术栈、路由、权限、状态管理、构建规则等关键信息
   - 调用后获取的约束作为实现硬约束，不得违背
2. **必须根据本阶段"技能强制调用规则"判断是否需要调用技能**，满足条件时立即调用，不得跳过。
3. 对项目技能中标记为 `not_applicable` 的能力，不做虚构实现。
4. 若现场发现新阻塞、环境问题、依赖问题或技能路线缺口，再回写更新，不得假装研发已完成。
5. 若已启用长任务机制（Stage 3），则实施过程中持续回写步骤状态。
6. **代码改动完成后，必须立即衔接 Stage 6 做内部验证**：
   - **禁止**在 Stage 5 完成后询问"功能是否正确"或"是否进入验证"
   - **禁止**输出"请确认功能实现是否满足需求"
   - 直接进入 Stage 6，执行验证后再等待用户确认
7. 若环境问题导致无法执行验证（如 lint/type/build/test 命令不可运行），则输出明确的环境修复建议并保持在 Stage 5，不得进入 Stage 6。

## 输出

- 代码修改
- 配置修改
- 必要的任务状态更新
- 若存在环境问题导致 lint/type/build/test 无法在当前环境完成，则输出明确的修复建议并保持在 Stage 5，不得把该结果当成可进入 Stage 6/7 的完成态

## 回退条件

- 若内部验证失败，回退本阶段继续修复。
- 若运行、lint、type、build 或测试因当前环境问题无法通过，停留在本阶段，先向用户说明修复环境所需动作；环境修复后继续 Stage 5，而不是进入 Stage 6 或 Stage 7。
