# Stage 8：交付续跑

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含交付确认内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "修复后会xxx" | 禁止在修复前承诺结果 |
| "新任务计划" | 禁止自创新任务列表 |

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出：`[交付续跑] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID

### 3. 必须等待用户确认 ⚠️ 强制规则

**⚠️ 重要：交付结果输出后，必须等待用户确认**

交付结果输出后：
- 输出交付摘要
- 输出确认提示语
- **结束当前回复**
- **等待用户回复"确认"或提出修改**

**禁止事项**：
- ❌ 禁止输出摘要后直接结束任务
- ❌ 禁止跳过用户确认环节

---

## 目标

- **用户确认的唯一节点**：在整个研发流程结束后，输出交付结果等待用户确认
- 如果用户提出修改，**立即回到 stage5** → 执行修复 → stage6 → stage7 → stage8 → 循环

---

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：更新状态文件

**首先更新状态文件**：

根据当前任务ID找到对应的状态块：
- 查找 `<!-- TASK_{任务ID大写}_START -->` 到 `<!-- TASK_{任务ID大写}_END -->` 之间的内容
- 使用 edit 工具替换该状态块内容为：

```
**任务ID**: {当前任务ID}
**正在执行**: 交付续跑
**阶段**: stage8
**状态**: in_progress
**下一步**: 输出交付结果，等待用户确认
```

---

### 步骤 2：汇总交付结果

**汇总以下信息**：
- 修改内容摘要
- 验证结果摘要
- 已知风险
- 后续建议

---

### 步骤 3：输出交付结果并附加确认提示语 ⚠️ 必须等待用户确认

**⚠️ 重要：输出交付结果后，必须等待用户确认**

输出交付结果：

```
以上是本次任务的交付结果。

修改内容：
- {修改文件列表}
- {简要修改说明}

验证结果：
- lint: 通过
- type: 通过
- build: 通过
- 功能验证: 通过

请确认是否有修改：
- 如有修改需求，请直接告诉我具体内容，我将回到实施研发阶段修复
- 如无其他修改，回复"确认"即可完成本次任务

您也可以明确指定回到某个阶段：
- "进入实施研发" / "进入代码修改"：重新开始代码修改
- "进入范围分析" / "进入需求分析"：重新分析需求
```

---

### 步骤 4：更新状态文件为等待用户

**输出后更新状态文件**：

```
**任务ID**: {当前任务ID}
**正在执行**: 交付续跑
**阶段**: stage8
**状态**: waiting_user
**下一步**: 等待用户确认交付结果
```

**⚠️ 重要：发问后必须结束当前回复，等待用户确认**

**⚠️ 禁止事项**：
- ❌ 禁止发问后继续执行其他操作
- ❌ 禁止跳过用户确认环节

---

### 步骤 5：用户确认循环机制

**用户答复后，根据意图执行对应动作**：

| 用户回复 | 意图类型 | 处理动作 |
| --- | --- | --- |
| "继续" / "确认" / "没问题" | 确认意图 | 输出完成提示语，任务完成 |
| 功能问题 / bug描述 / 修改内容 | 修复意图 | 回到 stage5 执行修复循环 |
| 资料补充 / 接口文档等 | 补充意图 | 回到 stage4 补充资料 |
| 新需求 / 新功能描述 | 新需求意图 | 回到 stage2 重新分析 |
| "进入实施研发" / "进入代码修改" | 切换意图 | 切换到 stage5 |
| "进入范围分析" | 切换意图 | 切换到 stage2 |

#### 5.1 用户提出修改时的处理流程

**用户提出修改时，按以下顺序执行**：

##### 5.1.1 更新状态文件为 stage5

```
**正在执行**: 实施研发
**阶段**: stage5
**状态**: in_progress
**下一步**: 根据用户反馈执行修复
```

##### 5.1.2 执行修复动作

- 调用 `./implementation.md`
- 根据用户反馈修改代码

##### 5.1.3 修复完成后自动循环

- stage6（验证） → stage7（文档同步） → stage8（交付确认）
- 再次等待用户确认

---

### 步骤 6：用户确认后完成任务

**用户确认无修改后，更新状态文件**：

```
**任务ID**: {当前任务ID}
**正在执行**: 任务完成
**阶段**: completed
**状态**: completed
**下一步**: 等待用户补充新需求或退出技能
```

**输出完成提示**：
```
[交付续跑] 任务ID: {当前任务ID}
本次任务已完成。
```

---

## 禁止事项

- 禁止用户提出修改后不切换到 stage5
- 禁止在 stage8 状态下直接执行修复（必须先更新状态为 stage5）

---

## 回退条件

- 用户提出修改 → **默认回到 stage5**（循环）
- 用户明确指定步骤 → 切换到指定步骤
- 用户确认无修改 → 任务完成
