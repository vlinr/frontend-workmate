# Stage 0：初始化

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含初始化内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "创建项目后要xxx" | 禁止承诺未来结果 |
| "后续将执行xxx" | 禁止输出未来计划 |
| 任务计划列表 | 禁止自创任务列表，必须使用状态文件的任务状态 |
| 多阶段内容 | 禁止在本阶段输出其他阶段的内容 |

**正确输出**：
```
[初始化] 任务ID: task_xxxxxxxx
正在初始化...
[初始化] 执行完成。接下来进入下一阶段：[项目扫描]。
```

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出必须包含任务ID：`[初始化] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID
- 禁止脱离任务上下文执行操作

### 3. 完成后自动进入下一阶段（不等待用户确认）

**完成本阶段后**：
- 输出阶段完成提示：`[初始化] 执行完成。接下来进入下一阶段：[项目扫描]。`
- 更新状态文件为 stage1
- **自动进入 stage1**，不等待用户确认

**注意**：stage0 → stage1 是自动衔接，无需用户确认。

---

## 目标

- 完成环境初始化、文件接收、基础状态初始化。
- **生成任务ID**：创建一个唯一的任务标识。
- **接收并记录用户诉求**：用户可能提供研发需求、项目信息等，本阶段只负责记录，不负责分析或实现。

## 内容处理规则（重要）

**本阶段职责边界**：

| 属于本阶段的内容 | 不属于本阶段的内容（记录到上下文） |
| --- | --- |
| 初始化脚本执行 | 项目分析、项目扫描 |
| 任务ID生成 | 范围分析、任务类型判断 |
| 用户诉求记录 | 研发实施、代码修改 |

**用户可以提供任何内容，本阶段只负责记录**：

```
用户可能提供的内容示例：
- "修复登录页面的验证问题"
- "新增用户管理模块，要有权限控制"
- "优化首页加载速度，目标是2秒内"
- "创建项目：React + TypeScript"

处理方式：
- 全部记录到任务上下文
- 不在本阶段分析或实现
- 等后续阶段处理
```

## 执行步骤概览

本阶段按以下顺序执行（详见下方"执行动作"部分）：

1. **生成任务ID**：立即生成并输出具体任务ID
2. **执行 init-skills.js**：执行脚本生成配置文件
3. **更新状态文件**：读取配置文件路径，编辑状态文件
4. **记录用户诉求**：建立最初需求锚点
5. **输出完成提示**：告知进入下一阶段

## 输入

- 用户原始诉求
- 当前上下文中的限制条件
- 用户附带的截图、设计图、报错信息或路径线索（若有）

## 执行动作

**按以下顺序严格执行**：

### 1. 生成任务ID（必须首先执行）

- 立即生成一个具体任务ID：`task_` + 8位随机字符
- 输出给用户：`[初始化] 任务ID: task_xxxxxxxx`
- 存入上下文变量 `current_task_id`
- **不要只描述规则，必须实际生成并输出**

### 2. 执行 init-skills.js（必须执行）

- 检查 `scripts/init-skills.js` 是否存在
- 若存在，立即执行该脚本
- 脚本会生成配置文件 `.fw-session-config.json`（包含 `rules_file_path`）

### 3. 更新状态文件（必须执行）

**脚本执行完成后**：

1. **读取配置文件**：使用 read 工具读取 `<技能包目录>/.fw-session-config.json`
2. **获取 rules 文件路径**：从配置中读取 `rules_file_path` 字段
3. **读取 rules 文件**：使用 read 工具读取该路径的文件
4. **编辑 rules 文件**：使用 edit 工具，在任务列表中新增任务状态块：

```
<!-- TASK_XXXXXXXX_START -->
**任务ID**: task_xxxxxxxx（第一步生成的任务ID）
**任务描述**: （用户原始诉求的简短描述）
**创建时间**: （当前时间戳）
**正在执行**: 初始化
**阶段**: stage0
**状态**: in_progress
**下一步**: 执行 init-skills.js 脚本
**用户提出修改时**: 无
**循环路径**: 无
<!-- TASK_XXXXXXXX_END -->
```

5. **同时更新活跃任务表格**：将新任务ID添加到活跃任务表格中

### 4. 记录用户诉求（必须执行）

- 接收用户原始诉求、截图、附件、路径线索
- 建立"最初需求锚点"，记录用户要解决的问题、目标页面/模块、期望结果

### 5. 输出完成提示

```
[初始化] 执行完成。任务ID: task_xxxxxxxx
接下来进入下一阶段：[项目扫描]。
```

### 禁止事项

- 禁止不生成具体任务ID就进入下一阶段
- 禁止不执行 init-skills.js 就猜测配置文件路径
- 禁止不执行编辑操作就进入下一阶段
- 禁止只说"要执行"但不实际执行工具调用

## 输出

- **任务ID**：必须输出给用户，便于后续引用
- 用户侧输出示例：
  ```
  [初始化] 任务ID: task_a1b2c3d4
  [初始化] 执行完成。接下来进入下一阶段：[项目扫描]。
  ```

## 回退条件

- 若后续发现任务目标理解错误，回退到本阶段重写。
- 若发现某轮回复在初始化阶段提前追问了实现细节，应视为越界，回退本阶段。
