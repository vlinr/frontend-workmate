# Stage 0：初始化

## 目标

- 完成环境初始化、文件接收、基础状态初始化，并判断是否可以进入 `Stage 1`。

## 第一步：更新状态文件

**进入本阶段后，必须立即执行以下编辑操作**：

### 编辑指令

1. **先读取配置文件**：使用 read 工具读取 `<技能包目录>/.fw-session-config.json`
2. **获取 rules 文件路径**：从配置中读取 `rules_file_path` 字段
3. **读取 rules 文件**：使用 read 工具读取该路径的文件
4. **编辑 rules 文件**：使用 edit 工具，将 `<!-- CURRENT_STATUS_START -->` 到 `<!-- CURRENT_STATUS_END -->` 之间的内容替换为：

```
**正在执行**: 初始化
**阶段**: stage0
**状态**: in_progress
**下一步**: 执行 init-skills.js 脚本
```

### 阶段完成后再次编辑

进入下一阶段前，再次使用 edit 工具替换状态内容为：

```
**正在执行**: 项目扫描
**阶段**: stage1
**状态**: in_progress
**下一步**: 执行 stages/project-scan.md
```

### 禁止事项

- 禁止不读取配置文件就猜测路径
- 禁止不执行编辑操作就进入下一阶段

## 输入

- 用户原始诉求
- 当前上下文中的限制条件
- 用户附带的截图、设计图、报错信息或路径线索（若有）

## 执行动作

1. **首要动作：检查并执行 `scripts/init-skills.js`**。若本技能中存在该脚本，必须立即执行。脚本用于把 `skills/curated`、`skills/external` 下的技能整理成可直接调用的公共技能包。执行后方可继续后续动作，若本轮未实际执行该脚本，则初始化阶段不得视为完成。
2. 接收用户原始诉求、截图、附件、路径线索，并建立本轮任务上下文。
3. 若本轮执行了 `init-skills.js`，用户侧提示语应收敛为"正在初始化..."与`[初始化] 执行完成。结论：初始化已完成。接下来进入下一阶段：[项目扫描]。`这类简短正文。
4. 初始化当前流程状态：记录当前阶段、【工作目录】下的前端项目是否可识别、是否属于前端任务、是否具备进入项目扫描阶段的最低条件。
5. 在本阶段建立"最初需求锚点"，只记录用户最初要解决的问题、目标页面/模块、期望结果；后续阶段不得覆盖该锚点，只能补充约束或实现路径。
6. **禁止事项**：初始化阶段不负责需求细化、不负责扫描项目、不负责分析项目结构、不负责生成项目 skill、不负责实现范围拆分。不得在初始化阶段输出任何关于项目分析的内容。
7. 新会话首轮，初始化阶段默认不主动提问；除非当前连"这是不是前端任务"或"是否存在可进入的【工作目录】"都无法判断，才允许在本阶段发出一个极小的澄清问题。
8. 初始化阶段禁止主动追问以下内容：页面实现范围、接口字段、交互细节、表单校验、还原标准、改动边界、UI 组件选型、登录成功/失败行为、任务拆分与研发方案、项目结构分析；这些全部属于后续阶段。
9. 对齐 `templates/intake/request-brief.md`。

## 输出

- 内部需要记录最小状态字段，可写入 `templates/intake/request-brief.md`：
  - `current_stage = stage0`
  - `current_stage_status`
  - `next_stage`
  - `stage_block_reason`
- 但这些字段默认不应原样暴露给用户。
- 初始化阶段的用户侧默认输出应收敛为：`正在初始化...` 或 `[初始化] 执行完成。结论：初始化已完成。接下来进入下一阶段：[项目扫描]。`
- Stage 0 的默认输出不应包含实现清单、接口问题清单、UI 还原清单、研发方案拆解或结构化状态字段列表。

## 回退条件

- 若后续发现任务目标理解错误，回退到本阶段重写。
- 若发现某轮回复在初始化阶段提前追问了实现细节或分析了项目结构，应视为越界，回退本阶段并收缩到"仅初始化执行 + 进入项目扫描阶段判定"。
