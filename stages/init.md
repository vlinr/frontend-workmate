# Stage 0：初始化

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含初始化内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "创建项目后要xxx" | 禁止承诺未来结果 |
| "后续将执行xxx" | 禁止输出未来计划 |
| 任务计划列表 | 禁止自创任务列表，必须使用状态文件的任务状态 |
| 多阶段内容 | 禁止在本阶段输出其他阶段的内容 |

**正确输出**：
```
[初始化] 任务ID: task_xxxxxxxx
[初始化] 执行完成。接下来进入下一阶段：[项目扫描]。
```

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出必须包含任务ID：`[初始化] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID
- 禁止脱离任务上下文执行操作

### 3. 完成后自动进入下一阶段（不等待用户确认）

**完成本阶段后**：
- 输出阶段完成提示：`[初始化] 执行完成。接下来进入下一阶段：[项目扫描]。`
- 更新状态文件为 stage1
- **自动进入 stage1**，不等待用户确认

**注意**：stage0 → stage1 是自动衔接，无需用户确认。

---

## 目标

- 完成环境初始化、文件接收、基础状态初始化。
- **生成任务ID**：创建一个唯一的任务标识。
- **接收并记录用户诉求**：用户可能提供研发需求、项目信息等，本阶段只负责记录，不负责分析或实现。

## 内容处理规则（重要）

**本阶段职责边界**：

| 属于本阶段的内容 | 不属于本阶段的内容（记录到上下文） |
| --- | --- |
| 初始化脚本执行 | 项目分析、项目扫描 |
| 任务ID生成 | 范围分析、任务类型判断 |
| 用户诉求记录 | 研发实施、代码修改 |

**用户可以提供任何内容，本阶段只负责记录**：

```
用户可能提供的内容示例：
- "修复登录页面的验证问题"
- "新增用户管理模块，要有权限控制"
- "优化首页加载速度，目标是2秒内"
- "创建项目：React + TypeScript"

处理方式：
- 全部记录到任务上下文
- 不在本阶段分析或实现
- 等后续阶段处理
```

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：生成任务ID

- 立即生成一个具体任务ID：`task_` + 8位随机字符
- 输出给用户：`[初始化] 任务ID: task_xxxxxxxx`
- 存入上下文变量 `current_task_id`
- 不要只描述规则，需实际生成并输出

---

### 步骤 2：执行 init-skills.js

- 检查 `../scripts/init-skills.js` 是否存在（相对于本技能包根目录）
- 若存在，立即执行该脚本
- **脚本会自动识别项目根目录**：
  - 从技能包位置（如 `e:\xxx\.ide\skills\frontend-workmate`）执行
  - 自动识别 `project_work_dir` = `staticConfigDir` 的父目录（如 `e:\xxx`）
  - **project_work_dir 是用户工作目录，不是前端项目目录**
  - 前端项目可能在子目录中（如 `e:\xxx\frontend`），但配置基于工作目录
  - 无需手动指定 `--workdir` 参数
- 执行示例：
  ```bash
  node ../scripts/init-skills.js
  ```
- **禁止传入前端项目目录作为 --workdir**：
  ```bash
  # 错误示例
  node ../scripts/init-skills.js --workdir "e:\xxx\frontend"
  
  # 正确：不传参数，自动识别
  node ../scripts/init-skills.js
  ```
- 脚本会执行以下改进逻辑：
  - **技能同步**：检查版本变化，有变化则更新（而非简单跳过）
  - **配置文件**：验证三核心目录是否正确，不正确则更新
  - **rules 文件**：检查模板是否有变更，有变更则更新
  - **状态文件**：保留现有内容（有任务数据，不覆盖）
- 脚本会生成或更新配置文件 `.fw-session-config.json`（存放在 `{project_ide_dir}`）

**注意**：即使技能已存在，脚本也会检查版本变化并更新，确保用户始终使用最新版本。

---

### 步骤 3：更新状态文件

**脚本执行完成后**：

1. **读取配置文件**：使用 read 工具读取 `{project_ide_dir}/.fw-session-config.json`
2. **获取三个核心目录**：从配置中读取 `static_config_dir`、`project_ide_dir`、`project_work_dir`
3. **读取状态文件**：使用 read 工具读取 `{project_ide_dir}/rules/fw-session-state.md`
4. **编辑 rules 文件**：使用 edit 工具，在任务列表中新增任务状态块：

```
<!-- TASK_XXXXXXXX_START -->
**任务ID**: task_xxxxxxxx（第一步生成的任务ID）
**任务描述**: （用户原始诉求的简短描述）
**创建时间**: （当前时间戳）
**正在执行**: 初始化
**阶段**: stage0
**状态**: in_progress
**下一步**: 执行 init-skills.js 脚本
**用户提出修改时**: 无
**循环路径**: 无
<!-- TASK_XXXXXXXX_END -->
```

5. **同时更新活跃任务表格**：将新任务ID添加到活跃任务表格中

---

### 步骤 4：记录用户诉求

- 接收用户原始诉求、截图、附件、路径线索
- 建立"最初需求锚点"，记录用户要解决的问题、目标页面/模块、期望结果

---

### 步骤 5：输出完成提示并自动进入下一阶段

```
[初始化] 执行完成。任务ID: task_xxxxxxxx
接下来进入下一阶段：[项目扫描]。
```

**完成后自动进入 stage1**（不等待用户确认）。

---

### 禁止事项

- 禁止不生成具体任务ID就进入下一阶段
- 禁止不执行 init-skills.js 就猜测配置文件路径
- 禁止不执行编辑操作就进入下一阶段
- 禁止只说"要执行"但不实际执行工具调用
