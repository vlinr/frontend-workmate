# Stage 7：文档同步

## ⚠️ 强制规则（必须遵守）

### 1. 单一阶段输出原则

**本阶段输出只能包含文档同步内容，禁止幻想未来阶段**：

| 禁止内容 | 说明 |
| --- | --- |
| "用户确认后会xxx" | 禁止幻想用户反馈 |

### 2. 任务ID携带原则

**本阶段必须携带任务ID**：
- 第一行输出：`[文档同步] 任务ID: task_xxxxxxxx`
- 状态文件更新必须携带任务ID

### 3. 完成后自动进入下一阶段

**文档同步完成后**：
- 不输出确认提示语
- 不等待用户确认
- 自动进入 stage8（交付续跑）

---

## 目标

本阶段主要实现**两个任务**：

1. **判断是否需要更新项目技能**
2. **生成/更新目录说明文档**

---

## 执行流程

**进入本阶段后，按以下顺序执行**：

---

### 步骤 1：更新状态文件

**首先更新状态文件**：

根据当前任务ID找到对应的状态块：
- 查找 `<!-- TASK_{任务ID大写}_START -->` 到 `<!-- TASK_{任务ID大写}_END -->` 之间的内容
- 使用 edit 工具替换该状态块内容为：

```
**任务ID**: {当前任务ID}
**正在执行**: 文档同步
**阶段**: stage7
**状态**: in_progress
**下一步**: 判断是否更新项目技能 + 生成目录说明文档
```

---

### 步骤 2：任务1 - 判断是否需要更新项目技能

**⚠️ 重要：此步骤涉及技能调用，需使用 skill 工具**

---

#### 2.1 加载现有项目技能 ⚠️ 技能加载节点

**⚠️ 重要：必须加载技能获取项目知识**

执行以下动作：

1. 加载技能 `fw-project-develop` 了解项目结构和技术栈
2. 从技能中获取项目的目录结构、技术栈、构建规则等信息

**⚠️ 禁止事项**：
- ❌ 禁止跳过技能加载直接判断是否更新

---

#### 2.2 分析本次代码改动 ⚠️ 技能加载节点

**⚠️ 重要：需要判断是否加载 fw-code-analysis-doc 技能**

执行以下动作：

1. 提取 Stage 5 实际修改的代码内容

2. **判断是否需要加载 fw-code-analysis-doc**：

   **需要加载的条件（满足任一即可）**：

   | 条件 | 具体判断 |
   | --- | --- |
   | 改动涉及新模块 | 新增目录或文件，现有项目技能未记录 |
   | 改动涉及复杂依赖 | 模块间新增依赖关系，需要更新项目技能 |
   | AI 无法自行分析 | 代码改动复杂，需要技能指导 |
   | 改动涉及核心架构 | 修改了项目的核心结构或配置 |

3. 若满足上述条件：
   - 加载技能 `fw-code-analysis-doc` 获取分析指导
   - 根据技能指导分析模块结构

4. 若不满足条件：
   - 直接分析代码改动内容

---

#### 2.3 判断是否需要更新

**需要更新的条件**：
- 新增了长期稳定的项目知识（如新的目录结构、新的技术栈、新的路由规则等）
- 项目技能中记录的信息已过时
- 发现了新的稳定项目约束

**不需要更新的条件**：
- 改动仅涉及当前任务的临时实现，不属于项目长期知识

#### 2.4 执行更新或跳过

- **需要更新**：将新的稳定知识合并到 `fw-project-develop`，输出：`已更新项目技能 fw-project-develop`
- **不需要更新**：输出：`经分析，本次改动不影响项目技能长期知识，无需更新`

---

### 步骤 3：任务2 - 生成/更新目录说明文档

**按以下步骤执行**：

#### 3.1 提取改动目录集合

- 从 Stage 5 的实际改动文件中提取所有涉及的目录

#### 3.2 逐目录处理 ⚠️ 技能加载节点

**⚠️ 重要：对每个改动目录需判断是否需要加载技能**

**对每个改动目录执行以下动作**：

1. **判断是否需要加载 fw-code-analysis-doc**：

   **需要加载的条件（满足任一即可）**：

   | 条件 | 具体判断 |
   | --- | --- |
   | 目录实现关系复杂 | 目录下文件数 > 5，或存在多层嵌套结构 |
   | 缺少说明文档 | 目录下无 README.md 或 AGENTS.md |
   | AI 无法自行分析 | 目录逻辑复杂、依赖关系不清晰 |
   | 涉及核心模块 | 目录是项目的核心业务模块 |

2. 若满足上述条件：
   - 加载技能 `fw-code-analysis-doc` 获取分析指导
   - 根据技能指导分析目录结构

3. 若不满足条件：
   - 直接读取目录内容进行分析

4. 检查目录下是否已有说明文档（README.md 或类似文档）
5. 若有 → 更新该文档内容
6. 若无 → 使用模板创建新文档

**⚠️ 禁止事项**：
- ❌ 禁止跳过技能加载直接创建文档

#### 3.3 输出处理结果

```
[文档同步] 已处理以下目录：
- src/pages/ → 已更新 README.md
- src/components/ → 已创建 README.md
```

---

### 步骤 4：输出衔接提示语并自动进入下一阶段

**文档同步完成后，输出衔接提示语**：

```
[文档同步] 任务ID: {当前任务ID}
文档同步完成。

处理结果：
- 项目技能：[已更新 / 无需更新]
- 目录文档：[已处理目录列表]

接下来进入下一阶段：[交付续跑]。
```

---

### 步骤 5：更新状态文件为下一阶段

**进入 stage8 前更新状态文件**：

```
**任务ID**: {当前任务ID}
**正在执行**: 交付续跑
**阶段**: stage8
**状态**: in_progress
**下一步**: 输出交付结果，等待用户确认
```

---

## 禁止事项

- 禁止在 stage7 暂停等待用户确认
- 禁止生成单一总文档（必须按目录逐个处理）

---

## 回退条件

- 若实现仍在频繁变化，可暂缓本阶段，待 Stage 6 稳定后再执行
- 若 Stage 6 未形成"通过"结论，不得进入本阶段
